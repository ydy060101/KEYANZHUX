## Decisions taken during T2.4

- **OCR engine is an optional install.** `paddlepaddle==3.2.0`, `paddleocr==3.7.0`, `paddlex==3.7.2` and the exact `opencv-contrib-python==4.10.0.84` that paddlex gates its pipeline on are grouped under the `ocr` extra in `backend/pyproject.toml`. Without them, `ocr.available()` is false, a scanned page yields no text and the worker logs a warning; the job reports 0 blocks rather than crashing (H08). `tests/test_ocr.py` skips in that case, so the suite stays green on a checkout without the OCR stack.
- **OCR render scale is 2.0, not 1.5.** At 1.5 the recogniser loses the section number of "6 Results" entirely (it reads "Results"), so the scanned Transformer's tree was missing a section; at 2.0 it reads "6 Results" and all 24 printed headings come back, for about one more second per page. At 2.5 and 3.0 the text is the same but the number glues on ("6Results"), which the heading rule now also accepts. This is recorded because the scale is a quality/throughput trade-off the card did not specify.
- **`torch` must be imported before `paddle`.** paddle's runtime load rewrites the DLL search path and torch then fails with `OSError: [WinError 127] ... torch\lib\shm.dll`. `app/ingest/ocr._engine()` imports torch first for this reason.
- **Three parser defects were found and fixed while making the scan comparable to its vector original.** None of them is a threshold change; they were corrupting text for every document:
  1. `pdfio.typed_blocks` skipped whitespace-only spans, so the explicit `" "` spans between words were dropped (`convolutionalneuralnetworksin`). It also concatenated a block's lines with no separator, so every line break glued two words (`relying` + `entirely` → `relyingentirely`). Both made search, MinHash and QA回验 compare non-words. Fixed by keeping space spans and joining lines with `join_lines` (de-hyphenating `transduc-` + `tion`).
  2. `parser._block_type` required a space after a bibliography label, so `[1]Jimmy Lei Ba` — how this PDF sets every entry — typed the whole vector bibliography as `paragraph` while the OCR copy typed it as `reference`. Two parses of one paper disagreed on 36 blocks. The lookup now accepts the label with or without the space.
  3. `assets._CAPTION` accepted a bare `.` as the label separator, so prose ("Table 2.1 shows the sizes") parsed as label "2" + text "1 shows the sizes" and the following length cap then dropped real captions. The separator is now a colon or a full stop followed by a space, and the 400-character cap is gone: GPT-3 and BERT both set legitimate captions of 500–900 characters.
- **`fingerprint.tokenize` folds typographic ligatures** (`ﬁ` → `fi`, `ﬂ` → `fl`, …). A vector PDF that sets "conﬁguration" and a scan of the same page that reads "configuration" are the same word; without folding, every such word counted as a difference. This is what makes the scan/vector pair reach `dedup_l3_minhash_jaccard` (0.8) — it measures 0.844, while unrelated fixture papers measure 0.000.
- **L3 no longer assumes cosine 1.0 when the embedding is missing.** The previous code defaulted `cos` to `1.0` whenever the model was unavailable, which put every upload above `dedup_l3_cosine_possible` and reported a "possible duplicate" whose "similarity 1.00" had never been measured (H02). Now a missing vector means the title/abstract branch cannot fire at all; only the MinHash body-overlap rule can, and its reason quotes the Jaccard it actually measured.

## Decisions taken during T2.5

- **Block and asset ids are page-scoped (`b{page}_{n}`, `eq{page}_{n}`).** Ids had to survive a resume: when a run stops after window 7 and restarts, window 8 must produce exactly the ids it would have produced in the uninterrupted run, or every chunk and anchor written before the stop points at nothing. A document-wide counter cannot do that — it depends on how many blocks the skipped windows produced — so ids are derived from the page they sit on. They stay unique because a page is parsed by exactly one window.
- **Four of the book's 541 pages are blank in the source.** Pages 2, 4, 10 and 12 have no text layer, no image and no drawing. "完整入库" (B3) is therefore checked as *every page that carries content*, and `check_long_book.py` prints the blank pages rather than counting them as a failure. 537 pages land.
- **Tokens are estimated as `len(text) / 4`, not counted with bge-m3's tokenizer.** Chunking runs for every window of a 541-page book inside the parse worker; loading a multi-GB tokenizer there to size a buffer is not worth the memory against a 300–600 target. `CHARS_PER_TOKEN = 4` is the usual English prose ratio and is deterministic (H06). T3.1 can re-measure chunk sizes with the real tokenizer once bge-m3 is loaded, without changing the chunk boundaries' logic.
- **Section summaries are extractive, not LLM-written.** `rag/summary.py` takes the first ~400 characters of the section cut at a sentence boundary. An LLM summary per section would be 169 calls for this book during parsing, and each sentence would need an anchor to satisfy H01. The extractive text is by construction verbatim from the section, so the two-level index can cite it directly. A model-written abstract can be added later as an enrichment pass with its own anchors.
- **Embeddings are left NULL in T2.5.** bge-m3 is not yet downloaded (huggingface.co is unreachable; the mirror download is incomplete), and `chunks.embedding` is nullable. `write_index` writes text, `tsv` (a generated `to_tsvector('english', text)`) and `block_ids`, so lexical retrieval works now; T3.1 fills the vectors and adds the HNSW index.
- **A chunk open at the end of a window is not emitted until the next window or the flush.** A paragraph can continue past a 20-page boundary; emitting early would cut it in half and produce two half-chunks for the same passage. The consequence is that the last chunk of a window is queryable one window later, which the early-visibility check accounts for.
- **`tools/check_long_book.py` counts windows from the progress event stream, not from table polling.** The first version polled `jobs` every 0.5 s and caught 15 of 28 windows — a property of the script, not of the parse. It now subscribes to `job:{id}` (the channel the SSE relay reads) before the parse starts, so every published window is counted, and drains the buffer after the job returns.
- **No migration tool yet.** `tools/sync_schema.py` fills the gap for T2.5's two schema changes: it creates `section_summaries` and rebuilds `chunks` (whose `tsv` column changed to a generated tsvector), and it refuses to rebuild `chunks` once it holds rows. Alembic is still on the pending list; until it lands, schema changes need a script of this kind.

## Decisions taken during T2.6

- **The outline is built from `section_summaries`, not from blocks typed `heading`.** The book has 1 014 blocks typed `heading` but only 169 sections, so an outline keyed by block produced one section id six times over: React rejected the duplicate keys and the jump target was ambiguous. The section index already has one row per section, so it is the outline; the jump target is found by taking the first heading block that carries each `section_id`, which is the heading that opened the section. `BlockRow.page` breaks the tie inside `reading_order` because each window numbers its blocks from 1.
- **A citation is only recorded when every number in its marker names an existing entry.** The regex fallback reads brackets out of prose, and a machine-learning text is full of them: `sig[z] ∈ [0, 1]`, `r[0]`, `log[1]`. Before this check the book produced 24 "citations" pointing at `r0` and `r1`, neither of which exists — every one of them an interval or an index. The marker is now taken whole or not at all (keeping the numbers that happen to resolve would turn `[0, 1]` into a citation of entry 1), and a bracket glued to a letter or digit (`r[0]`) is rejected as an index. This is the same rule H02 applies to generated text, applied to extraction.
- **A regex citation's hit box is one line at the marker's estimated offset, not the whole block.** The text fallback has no glyph geometry, so the horizontal position is interpolated across the block's width. Anchoring to `block.bbox` gave 300–500 pt tall boxes that swallowed every click on the paragraph; the reader's marker boxes are 6–20 pt.
- **The bibliography is split per page, not per document.** A book's text block shifts between verso and recto pages — this one by 39 pt — so one book-wide left margin makes every even-page entry look like a continuation of the entry above it (605 entries, one of them 4 661 characters). Columns are found per page from the right-edge clusters, and a block that spans the page (a running head, a centred footer) belongs to no column: taking the nearest one made each of them start a bogus entry, which is how 376 real entries became 704 before the rule and 1 198 after it. Within a page the walk goes column by column, because reading order interleaves the columns.
- **The end-of-parse bibliography pass replaces its rows rather than adding them.** Re-parsing a document — a retried job, or a re-upload that dedup maps back to the same id — found the previous run's `c1`, `r1` rows still there and died on the primary key at 97 % progress, after ten minutes of parsing. `persist.replace_bibliography` deletes both tables' rows for the document first (H12).
- **`documents.meta` stores the metadata as JSON.** The reader's 概览 card needs title, authors, abstract and their anchors, and 01 §4 has no column for them. Recorded as CR-006.
- **`assets.html` holds a table's HTML rendering.** T2.6 requires tables to render as HTML with a 查看原图 toggle; the parser already produced `table.to_html()` but there was nowhere to keep it. Recorded as CR-007.
- **`section_summaries.level` holds the heading depth.** The outline renders as a tree, and the depth was being recovered from the title's numbering in the API — which fails on an unnumbered heading. Recorded as CR-008.
- **`page` was added to the citation and reference payloads.** The reader has to draw a marker's box on the right page; deriving it from `block_id` on the client would duplicate the id scheme in TypeScript. Additive, recorded as CR-009.
- **A caption need not be punctuated after its number.** The book sets every caption as "Figure 1.1 Machine learning is an area of…", with no colon, and prints 290 of them — while T2.4 had narrowed `_CAPTION` to require a colon or a full stop precisely because "Table 2.1 shows the sizes" was being misread. Both constraints are satisfiable: the punctuation is optional, and what separates the two is the capital that follows (a title starts a phrase, a sentence continues one). `Figure 1.2 depicts several regression problems` is prose on page 16; `Figure 1.2 Regression and classification problems.` is its caption on page 17. Before this the book's figure and table lists were empty and every one of its 272 captions was invisible to the reader.
- **The table detector is asked with every strategy, and its answer must sit inside the crop.** The default strategy found no table at all on 11 of the 15 pages checked, and the `text` strategy returns one box spanning the whole page — which overlaps every table region on that page, so the old "shares any area" test accepted it and the reader would have shown the page's body text as the table's cells. `lines_strict`, `lines` and `text` are now all tried, and a candidate must be no more than 1.5× the crop's area with at least 70 % of itself inside the crop. Coverage on the fixture papers is still partial (1 of 4, 1 of 7, 0 of 13): their tables are borderless and set in a single column of text, which PyMuPDF's detector does not separate into cells. The crop is the fallback 02 §4.2 asks for, and it is written for every table.

## Decisions taken during T3.1

- **The embedding pass is its own job (`kind="embed"`), not a step of the parse.** bge-m3 is a 2 GB local model that takes minutes to load; putting it inside the parse would mean no window is searchable until it is loaded, which breaks T2.5's "已完成窗口可提前检索" and H08. The parse still writes chunks with `embedding` NULL and a generated `tsv`, so lexical retrieval works immediately; `POST /documents/{id}/embed` fills the vectors when the model is available, and is resumable (it selects `embedding IS NULL`) and idempotent. Recorded as CR-011.
- **The vector index is HNSW with `vector_cosine_ops`.** bge-m3 vectors are L2-normalised at encode time, so cosine and inner product rank identically, but the query uses cosine and the index has to match the operator or PostgreSQL silently falls back to a sequential scan. `m=16, ef_construction=64` are pgvector's own defaults for a corpus of this size (thousands of chunks, not millions).
- **Blocks with no letter in them are page furniture and are not chunked.** Transformer v1 has 54 such blocks (folio numbers, a stray `√`) and GPT-3 has 76; each was becoming a chunk whose entire text was "3", competing with real paragraphs in retrieval. The rule is `len < 40 chars AND no letter`, so a short word ("Yes") and a numeric table row are both kept — the length cap is what tells them apart.
- **An overlap tail that closes on its own is dropped, not emitted.** When the tail of a chunk was carried forward and the next block started a new section, the tail was emitted alone — a chunk wholly contained in its predecessor. GPT-3's fixtures produced two before the guard. A chunk that adds no block the previous one did not already have is an echo, and retrieval would return the same text twice for one query.
- **Chunk sizes are estimated with `len / 4`, and the statistics are reported rather than enforced.** 01 §9's 300–600 is a target: a section that is one paragraph is one short chunk, and a single block over 600 tokens cannot be split without cutting a sentence. The parse result now carries the distribution (`chunks` in the job result) so a chunking regression is visible without reading the rows, and the tests assert what is hard (no cross-section chunk, every chunk names its blocks, the median is a real paragraph, no echoes) rather than a percentage that a legitimately short section would fail.
- **The bge-m3 weights came from ModelScope, not the Hugging Face mirror.** hf-mirror.com delivered the 2.27 GB `pytorch_model.bin` at ~0.3 MB/s and dropped the connection repeatedly; the Hugging Face Xet transfer path returned 401 on this machine. modelscope.cn served the same file at 3–6 MB/s, and `curl -C -` resumed after each drop. The file is placed directly in the HF cache snapshot, and the tokenizer files (`tokenizer.json`, `sentencepiece.bpe.model`) were fetched the same way. This is a download workaround, not a code change: `Embedder` still loads by model name through `sentence_transformers`, and a machine with working HF access needs none of it.

## Decisions taken during T3.2

- **BM25 is PostgreSQL full-text search, not `rank_bm25`.** 01 §3.1 allows either. The GIN index over the generated `tsv` already exists (T3.1), so the lexical retriever is one SQL statement over the same table the vector stage reads: no second index to rebuild after every window commit, no divergence between what is stored and what is searchable, and no per-process copy of the corpus. `ts_rank_cd` is used because cover density is what "the passage about X" means — terms near each other, not merely present.
- **The BM25 query OR-s its terms; it does not AND them.** The first version used `websearch_to_tsquery`, which requires every word of the question to appear in one chunk. On the real models that returned nothing for 5 of the 8 golden questions — "How many warmup steps does the learning rate schedule use?" demands "schedule" as well as "warmup", and the answering passage says "we increased the learning rate linearly for the first warmup_steps training steps". A question is not a search box query: the lexical stage has to rank by how many terms match and how close they are, which is what `ts_rank_cd` does over an OR-query. With the fix every golden question has 27–30 lexical candidates out of 45 chunks, and the hybrid is genuinely hybrid. The query is rebuilt from `[A-Za-z0-9]+` runs before being handed to `to_tsquery`, because `to_tsquery` has its own syntax (`&`, `|`, `!`, `:`, parentheses) and a question containing one would change the query or raise.
- **The reranker's score replaces the fused score on each hit; the RRF value is kept alongside it.** H03 compares `QA_MIN_SCORE` against the top hit's score, and an RRF value is on a completely different scale (≈0.016–0.033) from a cross-encoder's (0–1), so leaving the fused value in `score` would make the threshold either always pass or always refuse. The fused value stays in `hit.rrf` and both stages' ranks stay on the hit, so a surprising order can be explained without re-running anything.
- **A `doc`/`set` scope with no document ids matches nothing; only `all` searches the library.** Failing closed is the only safe reading: a client that meant the whole library sends `all`, and an empty list is a bug on its side that must not silently become a library-wide search. A question answered from a paper the user did not select is the worst failure mode this system has.
- **Each stage degrades independently, and the result says which ran.** No embedding model → BM25 order; no reranker → fused order; both cases are recorded in `result.stages` (`vector`, `vector_available`, `reranked`). A caller can therefore tell a degraded answer from a full one instead of assuming the ranking used every stage (H08). The embedding stage is skipped entirely when the model cannot load, rather than raising: retrieval is on the QA path, and a question over a library that has no vectors must still be answerable from the text.
- **The golden set checks needles read out of the fixture, not chunk ids.** Each expectation is a literal phrase from the paper ("warmup_steps = 4000", "Pdrop = 0.1"), checked against the text of the returned chunks. Re-chunking the paper — a different window size, a chunker change — therefore does not invalidate the test, and the test cannot be satisfied by a lookup table (H05). The same set is used by `tests/test_retrieval.py` (stub embedder) and `tools/check_retrieval.py` (real bge-m3 + bge-reranker), so the unit result and the acceptance number describe the same questions.
- **The bge-reranker-v2-m3 weights were staged from ModelScope, like bge-m3.** 2.27 GB over the Hugging Face mirror had already failed once for bge-m3 (Xet 401, then repeated drops at ~0.3 MB/s); ModelScope served the reranker at ~3 MB/s in one pass. The files are placed in the HF cache snapshot under `.runtime/models/`, so `Embedder` still loads by model name and a machine with working HF access needs none of this.

## Decisions taken during T3.3

- **The answer is generated non-streaming and streamed per verified sentence.** H04 requires a whole sentence before any of it can be shown, and H06's cache only applies to non-streaming calls (the gateway cannot cache a token stream). So `run_qa` calls the model once at `temperature=0` on the `strong` tier, verifies the full reply, and the endpoint emits one `token` event per surviving sentence. The SSE stream is still incremental at sentence granularity, the joined tokens equal `done.answer` exactly (tested), and a repeated question hits the gateway cache. Raw token streaming would trade both H04 and H06 for a cosmetic effect.
- **H03's threshold only applies when the reranker actually ran.** `QA_MIN_SCORE=0.35` is calibrated on the cross-encoder's 0–1 score; without the reranker a hit's score is an RRF value of ≈0.03, so applying the same threshold would refuse every question whenever the 2.27 GB model is unavailable. When `stages.reranked` is false the answer proceeds and carries a `weak_support` flag saying the ranking is degraded (H08), so the user can tell why it may be worse. The acceptance refusal rate is measured with the real reranker.
- **A sentence that cannot be verified is deleted, not softened — and if nothing survives, the answer is a refusal.** H01 says a conclusion without an anchor must not be output, so an uncited sentence is dropped and flagged `uncited_claim`, a number/name/formula absent from the cited text drops its sentence with `ungrounded_number`, and an out-of-range marker is removed with `invalid_citation`. If every sentence goes, the response is the same refusal card as a low score; showing a partial answer whose support was just proven missing would be worse than saying the evidence is insufficient. The dropped text stays in `flags` so the deletion is auditable.
- **The anchor is the block inside the cited chunk that best matches the sentence.** A chunk spans blocks and often pages; anchoring to its first block would put the highlight on the wrong page roughly half the time. The block holding the most verified tokens wins, ties keep reading order (H06), and if the chunk has no `blocks` row the citation is dropped rather than given an invented bbox (H01).
- **Targeted extraction runs on `fast` and its output is nulled unless verbatim in the block it names.** 01 §6 assigns field extraction to `fast`; the model's `evidence` index must be in range and the value must occur literally in that block's text, otherwise the field becomes `null` and never reaches the generator. A gateway failure during extraction is logged and degrades to plain generation (H08) instead of failing the question.
- **`mode=compare` is rejected with `mode_not_implemented` until T3.4.** Returning a single-document answer under a `compare` request would mislabel it; the contract's `compare` response is a table, which T3.4 builds.
- **The golden set now has the card's 20 single-document questions and 5 unanswerable ones; the 10 cross-document entries arrive with T3.4.** 01 §9 asks for at least 30 in total, but cross-document questions cannot be written before the compare path exists. `tests/test_golden_qa.py` checks every needle against the fixture's pages, so a wrong page or a typo fails the suite instead of quietly lowering the acceptance number. The 5 unanswerable questions include one with high lexical overlap ("How many TPUs did BERT use for pretraining?") to test the model-side refusal, not only the score gate.
- **The anchor and the quote pivot on the rarest verified token in the chunk.** The first acceptance run scored 19/20: q17's chunk spans pages 6–7, the answer "36M sentences" is on page 7, but the sentence also contains "WMT", "2014" and "English-French", which the page-6 block shares — a match-count tie resolved to page 6, and the 200-character quote around the first token stopped before the number. Counting *distinct* matches treats a term that appears everywhere the same as a one-off number. Weighting each matched token by 1/frequency fixes the real case (the number occurs once, so it wins) and is a general rule rather than a patch for one question: the token that locates a fact is the one the chunk does not repeat. Ties still keep reading order (H06).

## Decisions taken during T3.4

- **Comparison retrieves per cell, not once for the whole table.** Each dimension × paper pair runs its own `scope=doc` retrieval with the dimension as the query. A single multi-document retrieval would let one paper's passage win the top-k and then be reused as if every paper had said it; scoping per cell is what makes "未在原文找到" meaningful. The question is not appended to the query: it usually names the other papers, and those names would pull each cell toward the wrong document's vocabulary.
- **A cell below `QA_MIN_SCORE` is "未在原文找到", not a refusal of the table.** H03's gate is applied per cell, where the cross-encoder score is a statement about that paper and that dimension. Absence is a finding the table must show; only when *every* cell is empty does the response become a refusal (and even then the empty table is returned, so the user can see what was compared).
- **Cell values are copied verbatim and rejected otherwise.** The extractor runs on the `fast` tier — 01 §6 assigns field extraction there — and returns the block number it copied from. The value must occur literally in that block (H04), and the anchor must come from a block that itself contains the value (H01); a value that spans two blocks is dropped rather than anchored to the nearer one. This is stricter than a human table would be: GPT-3's layer count will be the string `96`, not `96 layers`, because the source's column header supplies the noun. The dimension label supplies it in the UI.
- **Dimensions are proposed on `strong`, then sanitised.** 01 §6 lists 多文对比 under `strong`, and choosing what to compare is the analytical step; the per-cell extraction is a field lookup. Proposed dimensions are trimmed to 60 characters, deduplicated, capped at five, and any label containing a digit is discarded: a row header like "12 layers" would put an unanchored fact at the top of the table (H02). A failed proposal falls back to five fixed architecture dimensions with a `weak_support` flag (H08).
- **The summary is counted, never generated.** Prose synthesis would be a set of conclusions about the papers, and a one-line summary has no anchors to attach to them (H01). So the summary states how many cells are grounded, which dimensions no paper covers, and which paper has no evidence at all — every word of it derivable from the table. It follows the question's language (CJK detector) while cell values stay in the source language.
- **Cells are keyed by `doc_id`, and `done` also carries `documents` (`doc_id` → title).** `openapi.yaml`'s `CompareTable.table[].cells` is an object keyed by document; the extra `documents` map lets the client render column headers without a second request. It is additive: no existing field changed, and `QAAnswer` remains valid (`answer` is the summary, `citations` is empty because the table's cells carry the anchors).
- **At most five papers per comparison; `scope=all` takes the five most recent ready documents.** Twelve cells already means twelve rerank passes; an unbounded table would turn one request into minutes of CPU work with no progress events in the contract's event set. Truncation is always flagged, never silent. An explicit scope keeps the user's order after missing ids are dropped and flagged.
- **The compare endpoint's client errors arrive as SSE `error` events (HTTP 200).** Resolving the scope needs the database, which happens inside the streaming task; making it a pre-flight check would mean a second query and a second code path. The event carries the H17 envelope with `compare_needs_two_documents` / `empty_scope`, and the T3.5 client renders it like any other error.
- **The acceptance substitutes GPT-3 for GPT-1/2.** 03's T3.4 acceptance names a GPT-1/2/3 table, but only GPT-3 is on arXiv; GPT-1 and GPT-2 are hosted on openai.com, which H09's downloader whitelist excludes. The comparison acceptance therefore uses Transformer, BERT and GPT-3 (`tools/check_qa.py compare`), which still exercises three real papers with per-cell provenance. Fetching the two missing PDFs by hand would not change the product's whitelist and is not required by any card's contract.
- **The golden set now has 10 cross-document entries (35 total).** x01–x10 cover layers, hidden size, heads, corpora, optimizer, architecture, objective, benchmark, positional information and hardware. x09 expects GPT-3 to be silent on positional information and the test asserts the strings really do not occur anywhere in that PDF, so the "未在原文找到" path has a verified source-side expectation. T3.6 will consume these entries in `make eval-qa`; this card only validates them against the fixtures.
- **H04's literal check gained a numeric-token boundary rule; it is shared by QA, extraction and anchors.** The first C1 run reported GPT-3's layer count as `12`. That string is a substring of `12288` (the real hidden size) and of `128` (the head width), so the old `contains` check passed while the value was wrong — a table-row example of exactly the failure H04 exists to prevent. `verify.grounds()` now requires a token containing a digit not to start inside a word or decimal and not to be the prefix of a longer number, while still allowing a unit suffix: `36` is grounded by `36M`, which the real q17 quote depends on. `verify_answer`, `pick_anchor`, targeted extraction and compare cells all use it, so the rule is one implementation rather than four. Unit tests pin `12` vs `12288`, `76` vs `768`, `12` vs `12.5`, `175B`, and `36M`.
- **The cell prompt forbids headings, captions, table headers and definitions, and asks for the paper's primary model.** The same run filled Transformer's architecture cell with the section title "The Transformer - model architecture." and GPT-3's with a definition of `dmodel`; both were literal, both useless. It also had to say which BERT/GPT-3 size a generic dimension means, so the prompt now prefers the primary (largest/headline) model and forbids taking a number from another table row. The gates cannot judge relevance, only literalness; these rules move that judgement into the prompt, and a cell with nothing relevant still becomes "未在原文找到" rather than a plausible-looking fragment. `CELL_K` is 4 (from 3) to give the extractor the table header alongside its row at no extra rerank cost — the cross-encoder already scores all 60 candidates.

## Decisions taken during T4.1/T4.2

- **T4.1 and T4.2 land in one commit.** The two cards share `translate/service.py`, `api/translate.py`, `TranslatePanel.tsx` and the acceptance tool, and the document path is a thin loop over the same `translate_text` the selection path uses. Splitting them would have meant committing a half-wired service and then rewriting it; the deviation is recorded here rather than papered over with a misleading message.
- **Formulas are protected by masking, with a per-segment retry when the model breaks a marker.** A translation that "tidies" `$d_{model}=512$` has changed the paper. `protect` replaces fenced/inline code, display/inline math, `\(...\)`, `\[...\]` and citation markers with `⟦n⟧`, and `integrity` checks that every marker survived exactly once. A model that drops one triggers `_translate_segments`, which translates only the prose between protected spans and copies the spans verbatim, so the fallback cannot lose a formula even when the model misbehaves. Integrity is checked on the *masked* output; checking after `restore` would flag every correct translation (the markers are gone by design) — the unit tests pin both directions.
- **The first-token acceptance uses the median of three real streams.** One sample is not a latency measurement: the gateway's own time to first token moved between 985 ms and 1531 ms across runs on this machine. The tool prints all three, checks every sample's LaTeX, and requires the median ≤ 1500 ms; the design overhead (masking, SSE frame, queue) is well under 100 ms on top of the provider's TTFT. The shorter system prompt (v1) was chosen for that budget, not for quality.
- **The whole-document job translates four blocks at a time and caches per block.** Sequential calls would take hours on a 500-page book and unbounded concurrency would hit the gateway's rate limiter; batches of four keep the rate limiter from pacing the run while staying deterministic in stored order. The cache key is `sha256(prompt version + direction + source text)`, so a re-parse that changes one paragraph re-translates one paragraph. The job renders Markdown/HTML at the end; `GET /documents/{id}/translation?format=` re-renders on demand from the same rows.
- **The T2 sample pairs a synthetic LaTeX paragraph with five real ones.** The parsed fixtures keep formulas as page crops and assets, not as text: across the library only seven paragraphs contain `$` at all and none is a real `$...$` span. The acceptance therefore puts the T1 sentence (three formulas) into a six-block synthetic document and translates it through the same job path as five real paragraphs from the largest document. This still exercises the real model and the real cache; the alternative — inventing a formula-bearing real block — would have been a lie about the fixtures.

## Decisions taken during T5.1/T5.6

- **`/discover/search` answers with the contract's `ScholarHit[]`; `ext_id` and `in_library` are additive fields.** The schema requires only `title` and `source`, but `/discover/fetch` is keyed by `{source, ext_id}`, so a hit without its source-specific id could be displayed and never imported. Both fields are extra properties, which the schema permits; no existing field changed. The frontend parses the wire shape itself instead of the generated client, because the generated types do not know the extra keys.

When at least one source answers, the API returns the merged hits and adds `Warning: 199 research-agent "<failed…> unavailable"`; the page shows a small notice naming the missing sources (H08). When *every* source fails, the request answers 502 `source_unavailable` instead of an empty array — an empty library is a different fact from an unreachable provider.

Every reason names the seed and the shared keywords, so the number on screen can be checked; the score is not a model's opinion. A failed seed contributes nothing but does not empty the feed. With no library the feed is `[]` and the page shows an empty state with a link to upload.

The page shows the `Warning`-derived notice naming it and keeps the merged hits; nothing is retried in a loop, and no key is required to run the project (H08). A key would be a `SEMANTIC_SCHOLAR_API_KEY` env addition, not a contract change.

## Decisions taken during T6.1/T6.2/T6.3

- **T6.1 and T6.2 land in one commit; T6.3 is its own.** `GraphNode.role` is required by the contract, and a role is defined by PageRank and in-degree, so a graph cannot be serialised honestly before the metrics exist; splitting them would have committed either a fake role or a half-used endpoint. The canvas is a separate card and a separate commit.
- **Title matching is containment of the title's tokens in the reference text, at the spec's 0.92.** A reference is a whole bibliography string, so a Jaccard union would be diluted by authors, venue and pages; containment is the token-set reading that survives real entries. The known limitation is a reference whose text contains a different paper's title as a subset ("Attention Is Not All You Need"); when both sides carry a year the veto catches it, and when neither does no rule can tell them apart from the reference string alone.
- **A year is checked only when both sides know one.** The parse pipeline stores `meta.year` for almost no document, so requiring a year would reject nearly every correct match. `doc_year` falls back to the two-digit year in the arXiv id (1706 → 2017); a reference year that contradicts a known document year vetoes the title match.
- **A selected document without any edge is not a node.** It has no role in 01 §5.5, and drawing it as "peripheral" would assert an out-citation the graph does not contain. It is listed in `metrics.isolated`, and the page states 未进入图的所选文献：N 篇.
- **Duplicate copies of the same paper compete for one edge.** Candidates are sorted by id and an equal match keeps the smaller id, so the other copy can end up isolated while the cited copy takes the edge. That is the library's duplicate (T1.2's dedup is where it should be resolved), not a matcher error; the UI shows the isolate count rather than hiding it.
- **The e2e's in-canvas assertion uses a dev-only handle.** The canvas is not DOM, so `CytoscapeGraph` stores the instance on its container under `import.meta.env.DEV` and removes it on unmount; the production branch is tree-shaken. `verify-graph.mjs` uses it to check that every visible node is inside the canvas after a layout switch — a real acceptance that a screenshot alone would not pin.
- **The timeline layout is a preset with x = year, and the fit zoom is clamped to 1.3.** Cytoscape has no timeline layout; unknown years go to a bottom row. A layout switch also stops a running selection animation first: the animation's fixed pan/zoom otherwise survives the switch, overrides the new fit and can leave a node off-canvas (the e2e's first run caught exactly this).
- **The API client's base URL is same-origin absolute and its `fetch` is resolved per call.** `openapi-fetch` builds a `Request`, which Node rejects for a relative URL, so the library hooks could not be rendered in vitest. Same-origin absolute URLs behave identically behind the Vite proxy and in production; resolving `globalThis.fetch` at call time lets a test stub it without resetting modules.
- **The `--*-text` state colours are now mapped in Tailwind.** `text-danger-text`, `text-warn-text`, `text-success-text` and `text-accent-text` were used across existing pages but absent from `tailwind.config.js`, so they generated no CSS and the text fell back to the inherited colour. The token values were already chosen for 4.5:1 contrast (CR-002); this makes the existing classes do what they say.

- **The provider returns top-level `abstract` / `introduction` / `related_work`, not the nested `sections` array the schema asked for.** The first live run parsed a valid `OutlineDraft` with `sections: []` and silently lost the prose; the raw response showed the model's natural keys. `OutlineDraft` now accepts both shapes, with the named fields taking precedence, and the prompt asks for the four keys explicitly. This is a provider-behaviour accommodation, not a contract change: the SSE `outline` object is our own event payload.

- **`verified` means a real record, with the year/author gates applied when the caller knows them.** For a bare title there is no expected year/author, so only the title gate applies; for an outline candidate, the search record's year and authors are compared with the verification record. A record whose title matches but whose year or author contradicts the candidate is rejected rather than silently swapped. The evidence (DOI/arXiv/URL) is copied from the winning record; this module never constructs a citation from a template.
- **An outline is a framework, not a report.** The prompt forbids claiming experiments were run, and a deterministic regex flags result-style sentences (`实验表明`, `results show`, `outperforms`) in the returned `flags`; missing placeholders are flagged too. ## Decisions taken during T7.2

- **The sandbox is a Python-level whitelist plus OS resource limits, not a container.** The host has no container runtime, and spawning an unrestricted interpreter would let a model-written script read the library, call the network or overwrite the repository. The runner is launched with `-I` in a fresh temp directory after an AST check; its builtins remove `open`/`eval`/`exec`/`compile`/`input`/`breakpoint`/`exit`/`quit`/`help`/`globals`/`locals`/`vars`/`getattr`/`setattr`/`delattr`, its `__import__` only resolves the whitelist (numpy, pandas, matplotlib, graphviz and the standard-library modules the scripts need), and `socket.socket`/`create_connection`/`getaddrinfo`/`gethostbyname` are replaced with failures. The parent enforces 20 s and 512 MB (H09) and returns a Chinese error instead of an exception; this is defence in depth, not a claim that Python-level checks alone are a security boundary.
- **The RSS monitor sums the process tree on Windows.** The venv's `python.exe` is a uv launcher that starts the real interpreter as a child, so sampling only the launcher reported ~5 MB while the child held ~333 MB. `_tree_rss` adds every descendant, and termination uses `taskkill /T` so the interpreter cannot outlive the timeout. This was caught by the memory-limit test, which initially timed out because the script touched one byte instead of every page.
- **Graphviz uses the built-in preview when `dot` is absent, and the response says so.** The preview reads the simple DOT subset the generator emits (nodes, labels, directed edges, `rankdir`) and lays it out in layers; it is not presented as Graphviz's layout. It is sized from the data extent so `set_aspect("equal")` cannot make `bbox_inches="tight"` explode, and each layer's x positions are spaced by label width so long labels do not overlap. The first live run exposed both faults: 6566×17207 px, then invisible arrows because the edge loop had shadowed the axis limits. A regression test asserts the image stays under 2000 px per side and that the band between root and children contains arrow pixels.
- **TikZ without a TeX installation degrades to source plus a note.** `pdflatex` is invoked with `-no-shell-escape` (or `tectonic`), and the PDF is rasterised with PyMuPDF; when neither executable exists, the API returns the validated source and `renderer: unavailable` with an explicit note. Installing TeX is not a reasonable requirement for the demo host, and returning an empty image would be worse than the source.
- **Mermaid is rendered by the frontend, not by a headless backend.** The backend validates syntax and returns the script; the acceptance check uses Playwright Chromium (`frontend/e2e/verify-mermaid.mjs`) because jsdom has no `SVGElement.getBBox`, which Mermaid calls before layout. The check asserts an `<svg>` with no console errors; it is the same browser path the T7.5 studio will use.
- **The repair loop stops on an unchanged script and keeps the last script when the repair call fails.** Re-asking the model for a byte-identical script spends tokens and cannot succeed; an LLM outage during repair would otherwise discard a script that may already be usable. Both cases return `errors` and a note (`未修改` / `修复中断`), so the UI can explain the state instead of showing a spinner. Generation and repair both use `temperature=0`.
- **`kind=matplotlib` is the Python sandbox; there is no separate `python` kind.** The contract's four kinds name the output formats, and Matplotlib is the only one that executes Python. Adding a fifth kind would be an unsupported extension of the contract. Requests with another kind are rejected by the schema (now wrapped in the H17 envelope).
- **FastAPI's 422 response was the one error outside the H17 envelope.** `RequestValidationError` is handled by FastAPI before the generic `Exception` handler, so an invalid `kind` or a missing field returned `{"detail": ...}` while every app error returned `{"error": ...}`. A dedicated handler now emits `invalid_request` with the encoded validation errors; a test pins the shape. This is a compliance fix, not a new endpoint.
- **The sandbox never inherits the server's environment, and its RNGs are seeded.** Removing `open` does not stop `pandas.read_csv` or `plt.savefig`, and inheriting `os.environ` would expose the DeepSeek key and database URL to any script that reaches `pandas.compat.os`. The child now receives only `PATH`, the Windows system variables, `TEMP`/`TMP` and `HOME` under the temp workdir, plus Matplotlib/TeX settings; the parent validator also rejects `read_*`, `to_*`, `savefig`, `imsave`, `np.load`, `np.savetxt` and similar file methods. `random` and NumPy are seeded to 0 before the script runs, so two runs of the same script produce byte-identical PNGs (H06); a script that calls its own `seed` still controls its output. This is still a Python-level sandbox, not a VM: a determined script can reach internals of the whitelisted libraries, which is why the process also runs with a timeout, an RSS ceiling and no network.

## Decisions taken during T7.4

- **`POST /translate/zh2en` is synchronous because the contract says so, despite H07.** `openapi.yaml` returns `TranslationResult`, not a `job_id`. The request is therefore bounded: 20,000 characters, 1,600-character chunks, four chunks in flight at a time, and the 30-second timeout on each call. A live abstract took 2.95 s; a full paper or book uses `POST /documents/{id}/translate`, whose worker already reports progress over SSE. If the contract later gains a job, `translate_academic` becomes its worker unchanged.
- **Chunks are split on paragraph, then sentence boundaries, never inside a protected span.** A cut that would land inside `$...$`, a backtick span, `\[...\]`, `\(...\)`, `[...]` or a Latin term is moved past the closing delimiter, so no chunk ever sends half a formula to the model. Paragraphs are rejoined with `\n\n`; the model is told to preserve paragraph breaks, and whitespace-only differences at chunk boundaries are not meaningful to the translation.
- **Term preservation is a check plus one retry, not a hard failure.** Every Latin term of three or more characters (minus a small English stopword list) must appear in the chunk's translation, case-insensitively; if one is absent the chunk is translated once more with the missing terms quoted back. The retry is skipped when a legitimate translation replaced the Latin word, and the endpoint still returns the second result rather than failing the request. This enforces the card's "保留术语" deterministically without pretending the model cannot paraphrase.
- **The cache is in-process, not Redis or PostgreSQL.** `cached` is an advisory signal for the writing studio's "use cache" affordance; the translation itself is deterministic at `temperature=0`, and a cache miss only costs a model call. A 64-entry `OrderedDict` keeps the working set bounded, and `clear_cache()` exists for tests. In a multi-worker deployment a second request may land on another worker and report `cached=false`; correctness is unchanged, and the document job's database cache remains the durable one.
- **`direction` defaults to `zh2en` although the contract marks it required.** The path itself fixes the direction, so accepting an omitted field is a strict superset of the contract; an explicit `en2zh` is a 400 with `invalid_request`, and an absent/unknown `block_id` is a 404 before any model call. This mirrors `SelectionBody`'s default and keeps a curl call short.
- **The response has no anchor, and that is not an H01 exception to hide.** A translation is a transformation of the supplied text, not a conclusion extracted from a document; the source text is the evidence and `block_id`, when supplied, is validated against the reader's block. The contract's `TranslationResult` has no `doc_id`/`block_id`, and inventing fields would be worse than recording the distinction. Document-level translation rows do carry `block_id` and are served with page/bbox by `GET /documents/{id}/translation`.
- **The academic prompt is versioned separately (`academic-v1`).** The block translator's prompt is deliberately generic (it also handles English→Chinese); this endpoint needs the register of a paper, the paragraph rule and an explicit no-preamble instruction. Both share `protect`, the placeholder-integrity fallback and `temperature=0`, so the formula guarantee is identical.
- **The live acceptance checks register with deterministic gates, not a model judge.** A1 requires zero CJK characters, at least three sentences averaging 8–45 words, the `$k=5$` formula and `[12]` byte-identical, all of RAG/Transformer/BLEU present, and no "As an AI"/"Translation:" preamble; A2 requires the identical request to be cached and byte-identical. The printed translation is the human-readable part of "符合学术语体"; the gates are what can be re-run.

## Decisions taken during T7.5

- **Visited workspaces are mounted once and then hidden, not unmounted.** Switching tabs must not discard a generated outline, an uploaded CSV or an edited figure script, and there is no draft persistence endpoint for them. The price is memory: the heavy work is lazy-loaded per workspace, and Mermaid/Monaco/ECharts only enter the page when their tab is first opened. The panels keep `role="tabpanel"`, `aria-labelledby` and `hidden`, so a hidden workspace is absent from the accessibility tree.
- **There is no mock or sample fallback anywhere in the studio.** Every panel calls its real endpoint; an outline cite key with no verified record is shown as an explicit `[待补充]` card, never as an invented reference, and the reference panel is empty rather than populated with examples (H02/H16). The only mock switch remains the existing `VITE_USE_MOCK` used by the library page.
- **References are the verification panel, not a fourth generated prose section.** 02 §4.6 lists "References" in the outline structure, but asking the model to write a bibliography would be exactly the fabrication H02 forbids. The draft's `references` array is produced from verified Crossref/OpenAlex/arXiv records, and the panel renders it with source links and BibTeX; the generated prose ends at Related Work.
- **Monaco is loaded from the installed package instead of the CDN.** The demo host must work without outbound access, so `ScriptEditor` imports both `monaco-editor` and its editor worker, installs `MonacoEnvironment.getWorker`, and only then calls `loader.config({ monaco })`. While that chunk loads — or if it ever fails — the same script stays editable in a plain textarea, so the workspace never offers a dead editor. The editor is a lazy 4 MB chunk and is not part of the initial page.
- **Mermaid renders in the browser; the other kinds use the backend's image.** The backend already validates Mermaid and delegates rendering (T7.2), because a headless renderer needs a real SVG layout engine. The frontend merges a browser Mermaid error with `FigureResult.errors`, shows both, and sends the description, errors and current script to the repair call, so "让 Agent 修复" cannot silently drop the user's edits.
- **ECharts draws the contract's 20-row preview, while stats, caption and PNG use the full data.** `DatasetView` is the only row-level payload in `openapi.yaml`; there is no full-data endpoint to draw from, and adding one would change the contract. The UI states the limitation next to the chart. For the acceptance CSV (6 rows) the preview is the whole file; the server-rendered PNG remains the authoritative full-data image.
- **A missing `done` event is an error, not a partial success.** `streamOutline` throws "生成中断，请重试" when the SSE body closes after stages but before `done`, and the panel shows the retry state. `toOutline` drops a reference without a title and ignores sections without a heading, so a malformed payload degrades to fewer honest items rather than half-rendered cards.
- **Vite pre-bundles Mermaid, Monaco and ECharts in development.** Without `optimizeDeps.include`, the first visit to a workspace made Vite discover the dependency, re-optimise and reload the page — the first e2e run lost its generated outline exactly this way. The e2e also clicks the tab twice around a possible reload, which is a no-op when the first load is stable.

## Decisions taken during T3.6

- **The evaluation reuses `tools/check_qa.py` instead of reimplementing retrieval and generation.** The card asks for a script that prints the three rates; `check_qa.py` already owns the real-model runs (Q1 and C1) and was the T3.3/T3.4 acceptance gate. `app.eval_qa` runs it as a child process, echoes its progress, and parses the printed summary, so the report and the acceptance gate can never disagree. A missing metric, a missing `Q1:`/`C1:` verdict, or a question/refusal row count that disagrees with the printed total makes the run fail rather than defaulting a value (H02/H05).
- **The report records ids, pages, scores and reasons, never generated answer text.** The check prints an answer snippet after ` | ` for human reading; the parser discards it before building `docs/eval-qa.json` and `docs/eval-qa.md` (H13). The scores are the reranker tops, so a reviewer can still see why an anchor or refusal happened.
- **The host has no `make`, so `tools.ps1 eval-qa` is the validated entry point.** `Makefile` still provides the contract's `make eval-qa` for machines that have make; on this host `.\tools.ps1 eval-qa` runs the same `python -m app.eval_qa`.
- **The golden set is 35 entries: 20 single-document, 10 cross-document and 5 unanswerable.** Every expected point was read from the fixture page while the entry was authored, and that reading is frozen as an assertion in `backend/tests/test_golden_qa.py` (the needle must occur on the named page). This makes the review repeatable, but it is the implementer's reading, not a second reviewer's sign-off; the report says so rather than claiming an independent human audit.
- **The reference runs the evaluation to completion before writing the report.** The full run is 20 QA questions plus 5 refusals plus the 3-paper comparison through real bge-m3, bge-reranker and DeepSeek; partial output cannot produce a report, and a timeout is a failure. The command and the four model names are copied into the report so a result cannot be attributed to a different configuration.

## Decisions taken during T4.3

- **The left column is the real PDF, not a second text list.** 02 §4.2 says the middle column splits into 原文 | 译文; keeping the actual rendered page preserves figures, tables, citation hit boxes and the reading experience of the source, and the right column carries the block-aligned translation. Both columns are still aligned by block id, but the original side's geometry comes from the page box and bbox rather than from a re-rendered paragraph list.
- **Scrolling is synchronized by block identity and the reading line, never by a scroll ratio.** A block's top on the PDF side is `page node offset + bbox.y × scale`; a translation row's top is its DOM offset. The block that starts nearest above the reading line (22 % of the PDF viewport, 18 % of the translation viewport) becomes current, and the other column is moved to that block. The Playwright check asserts the PDF lands on the block's computed top within 2 px, which a proportional implementation could not satisfy.
- **Two direction-scoped 240 ms locks plus an "already visible" check stop the feedback loop.** When the pane drives the PDF it suppresses PDF events for 240 ms; when the PDF drives the pane it suppresses pane events. The PDF→pane path skips the write when the target row is already inside the pane viewport, so a long paragraph does not yank the translation column on every block change. The e2e waits 700 ms after each interaction and requires both scroll positions to stay put.
- **A click on a translation row reveals the same block in the PDF, and the current row carries a left border.** This gives the reader a way back from a translated sentence to the source and makes the linkage visible; the row also exposes `data-page`/`data-bbox`, while the pane exposes `data-scale`, so the acceptance script can recompute the mapping without trusting the component's state.
- **Direction defaults to 英→中 and is switched explicitly.** The library's papers are English and `GET /documents/{id}/translation` defaults to `en2zh`; a Chinese document with only an `en` translation shows the empty state with 前往翻译 until the reader picks 中→英. Guessing from content would add a second request and could still be wrong for bilingual papers, so the explicit toggle stays.
- **Opening the pane or changing zoom re-aligns it to the PDF.** The initial mount can race the fit-width observer (the host narrows when the pane appears), and a zoom change moves every block; reusing the same block picker after those layout changes keeps the first visible row honest instead of aligned to the old scale.
- **All translated rows are rendered.** A 15-page paper produces 445 rows, which is comfortable; a fully translated 541-page book would produce roughly ten thousand rows, and the per-frame measurement of every row would need virtualisation. That scale is outside this card's acceptance (the translation of such a book is itself a long job) and is recorded here as a known boundary rather than hidden behind a pixel-ratio shortcut.
